# NEXT 整车跨面与素材编辑实施记录

日期：2026-11-12。范围：整车跨面图案方向、3D 调整框、素材属性与调色器。

## 映射与传播

旧 v21 的显式接缝只覆盖左右前后门及机盖两翼四对部件。v22 使用经世界空间审核的 723 条接缝连接 24 对相邻部件，包含前后保险杠、上下前翼子板、后翼子板及立柱、充电盖、前后 C 环。16 个车体部件连通，浮置尾翼独立。

93,356 个三角的世界坐标、paint UV、分类与源身份与 v21 逐项完全相等，保持用户按图片/PSD 整理的映射方式。接缝仅传递源图坐标，不填补玻璃、灯组及配件间的非漆面空隙。生成工具为 `next/tools/assets/connect-classified-paint-surfaces.py`，活跃资产为 `next/assets/paint/su7-v22-whole-car/paint-map.json`。

镜像根因是接缝端点的 reversed 标志被当成相邻曲面的展开方向。现在由连通片内部边的 winding parity 和面积加权外向方向确定 sheet orientation，端点标志只负责匹配端点。源面展开保持不变，相邻片继续使用同一张图案坐标。

v21→v22 仅允许固定、已验证几何完全相同的指纹对升级。当前工程、撤销和重做中的锚点一同更新，保留位置、尺寸、旋转、图层和素材，标记待保存；其他映射指纹不匹配仍拒绝编辑。没有恢复旧版本工程格式兼容。

## 编辑交互

原 3D 控制框对源 chart 之外的四角使用最近三角外推，在边缘和跨面处造成长线、交叉及异常四边形。现在用投影覆盖区域拟合正交屏幕矩形，保留四角、四边与旋转点；手势开始时冻结操作坐标轴，显示、命中和尺寸变换采用一致坐标。

点击邻面的传播片段时，抓取偏移取自源图片 UV，避免把目标部件 paint UV 与源面中心混算；无位移点击不重新锚定、不产生修改记录。比例锁同时作用于 2D 与 3D 八个缩放点，保持对角或对边中点；Shift 保留临时比例锁和 15° 旋转。

## 素材属性与颜色

右侧工程属性中的“素材属性”提供名称、X/Y、宽高（mm）、纵横比锁、旋转和不透明度。新图片默认锁比例，图片信息显示名称、像素尺寸、原始比例和工程内 PNG 存储格式。不会把设计单位误当作图片像素。

图形、文字及选中图层的颜色改为饱和度/明度二维色板与色相条，支持 RGB 0–255 和 HEX（3/6 位）。无效输入不提交，拖色期间本地预览、松开一次提交，支持键盘、Esc 取消和撤销。沿用软件自身深浅主题。

## 验证与边界

- Rust 核心回归包含精确资产指纹/几何相等、276 次局部覆盖查询、138 次双向外观主面方向验证、左右三部件连续传播、小素材对侧隔离及尾翼隔离。
- 控制框回归包含正交、不交叉、镜像观察方向、比例锁和固定对边。前端验证包含 4096 组 RGB/HSV 回转、HEX/RGB 校验和锁比例尺寸边界。
- 原生桌面回归使用 Release 程序与隔离工程目录；GPU 图像取自原生 wgpu 读回，不以 WebView 截图代替 3D 证据。最终 34 项全部通过：`next/.reports/smoke-1794415451228/result.json`。
- 真实 v21 当前格式工程升级的 5 项回归通过：`next/.reports/migration-1794415420692/result.json`。包括原文件不变、幂等、编辑/撤销/重做、无关指纹拒绝及保存重开。
- `pnpm build`、`pnpm test:core`（78 项）、`pnpm test:transforms`、`node tools/tests/test-editor-properties.mjs`、`pnpm check:boundary` 和 `git diff --check` 均通过。

最终 Release：`next/target/release/itasha-desktop.exe`，21,134,848 字节；SHA256：`919b5b46e6d451eea61aeb50057548c4c4db0d0b9e621602a5c45c6fea189abe`。启动时仍需随软件保留 `assets/paint` 与已处理模型资源目录。

部件连通不代表每个独立分类岛都自动连通；没有可靠对应的岛不臆造接缝。部分 C 环窄三角保留原 UV 的较大局部比例差，小图案可能不足以跨过间隙。复杂曲面展开不等于无畸变施工纸样。

后续修复：跨部件拖动现在通过 Rust `transport_orientation` / `transport_anchor` 搬运方向。使用源/目标真实三角的 UV 导数及外向法线，以两切平面间的最短旋转搬运图片纵轴，再求目标 chart 的旋转角；chart 手性变化由 flipX 补偿，抓取点偏移同步转换。以手势原始状态计算，避免逐帧累积误差，宽高及比例锁不变。

2D 经受会话校验的 `viewport_transport` 使用同一算法；请求串行并合并过时位置，松开等待末次预览后只提交一次，取消丢弃迟到结果。3D 在原生指针处理中调用相同 Rust 函数；拖动控制框只重置角度基准，不把 UV 角度补偿误当成用户旋转。

方向保持指随真实曲面法线转折、消除 chart 排布引起的转向和镜像，并非将图案强制固定在一个世界平面。保留原分类 UV 及矩形图层模型，因此不新增剪切自由度，也不承诺消除源 UV 的非等比畸变。
