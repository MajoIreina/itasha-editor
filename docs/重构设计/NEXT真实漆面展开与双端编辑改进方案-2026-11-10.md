# NEXT 真实漆面展开与双端编辑改进方案

日期：2026-11-10。对象：`L:/SU7/痛车编辑器-下一版/next`。

状态：设计方案；本轮检查代码、模型 UV 属性及既有验收资料，未修改编辑器实现，未执行新的交互复现或曲面展开。下文性能、精度门槛均为建议验收目标，不是已达成结果。

## 1. 本轮已确认的需求

1. 仅对实际裸露的车漆面建立 3D→2D 展开映射。
2. 整车视图采用用户手稿的布局：车头朝上，前保位于顶部，机盖居中，左右翼子板与四扇车门分列两侧，尾部区域位于下方。具体轮廓取自实际面片，手稿确定空间组织，不把部件强制变为矩形。
3. 可切换“整车拆开展平”和“单部件编辑”。两种 2D 视图与 3D 共用素材、映射、选择和历史。
4. 2D、3D 都能移动、旋转、缩放同一素材，拖动中另一侧同步预览。
5. 一个素材能自动跨越允许连接的多个漆面，不要求用户拆图、复制或逐片对齐。
6. 部件划分按用户确认的实际结构建立，不能把当前 GLB 节点、材质槽或运行时 19 个区域直接当作实车分件。
7. 用户已明确：“穿管 A 柱”指与后翼子板连为一体、沿侧窗上沿延伸至 A 柱的整段外板。左右分别归属相应后翼子板总成，不能人为拆成独立的 A 柱部件。

这次需求更新取代旧记录中“跨面图层在 2D 只能选中、不能拖动”的限制。

## 2. 现状与根因

### 2.1 当前实现是参数投影，并未完成实际曲面展开

- [surface.rs:418](L:/SU7/痛车编辑器-下一版/next/crates/renderer/src/surface.rs:418)：顶部以 `(z,x)` 生成坐标；环绕以椭圆角度/弧长近似和高度生成坐标。
- [artwork.wgsl:13](L:/SU7/痛车编辑器-下一版/next/crates/renderer/src/gpu/artwork.wgsl:13)：片元再次按世界位置计算以上坐标，没有采样专用的漆面展开 UV。
- 顶部公式丢弃高度，环绕公式丢弃径向位置。因此不同深度的面可以具有相同素材坐标。该多对一关系从公式即可确认；具体误填部位仍应加入真实交互复现。

### 2.2 已有深度测试没有解决素材覆盖归属

[artwork.rs:59](L:/SU7/痛车编辑器-下一版/next/crates/renderer/src/gpu/artwork.rs:59) 已开启 `LessEqual` 深度测试。但同文件 [375 行](L:/SU7/痛车编辑器-下一版/next/crates/renderer/src/gpu/artwork.rs:375) 在跨面模式允许所有注册编辑面进入绘制，再依赖公式、法线与图片范围筛选。

这可以保证当前相机下前方几何挡住后方片元，却不能保证素材只属于用户选择的曲面邻域。换一个观察角度，其他收到相同素材坐标的面仍可能出现图案。修复重点必须包括明确的目标三角面集合，不能只调整深度偏移或法线阈值。

### 2.3 2D 轮廓没有保存可逆的面片身份

[DesignCanvas.tsx:23](L:/SU7/痛车编辑器-下一版/next/src/features/editor/DesignCanvas.tsx:23) 把不同部件投影合成一个 Path2D；[130 行](L:/SU7/痛车编辑器-下一版/next/src/features/editor/DesignCanvas.tsx:130) 根据第一个包含指针的轮廓选择部件。重叠区域缺少 `triangleId + barycentric`，无法可靠判断用户指的是哪个实际曲面。

[surface.rs:607](L:/SU7/痛车编辑器-下一版/next/crates/renderer/src/surface.rs:607) 将外露采样片段降为二维点；它们没有作为同一份受限三角面集合贯穿 3D 贴花和拾取。当前 [interaction.rs:108](L:/SU7/痛车编辑器-下一版/next/crates/renderer/src/interaction.rs:108) 的命中结果只保留部件、世界位置和法线，且拾取注册粒度仍以网格为基础。

因此还存在 2D 可编辑域、3D 拾取域与 3D 实际绘制域不完全一致的结构性风险。

### 2.4 现有分件与同步方式需要调整

- `SU7_SURFACES` 中部分区域依靠空间包围盒裁切合并网格；这不等价于真实钣金接缝。
- [viewport.rs:627](L:/SU7/痛车编辑器-下一版/next/src-tauri/src/platform/viewport.rs:627) 按命中法线在 `belt/top` 间切换；一张图片不能依靠这种切换稳定地同时包覆侧面与上表面。
- [DesignCanvas.tsx:123](L:/SU7/痛车编辑器-下一版/next/src/features/editor/DesignCanvas.tsx:123) 的拖动只更新前端临时状态；原生拖动则在渲染线程临时预览，松手后提交。当前并非拖动中双端连续同步。

### 2.5 已有资产可以继续利用，但 UV 需要重新验收

只读检查当前 `3D/Blender/software/body.glb`：适配器引用的 13 个来源节点都带 `TEXCOORD_0`，这些节点未带 `TEXCOORD_1`。现有加载器在缺失第二套 UV 时复制第一套。这说明模型具备源 UV，但不能据此认定它是唯一、等比例、按实车部件组织的涂装 UV。

保留原有材质 UV，新增专用 `paintUv` 和映射附属文件。必要时复用经验证的原 UV 岛，不能直接把原 UV0 当作新的整车编辑画布。

## 3. 按真实结构建立部件层级

用户确认的部件，加上前面手稿明确的机盖，作为必需核验清单：

| 逻辑部件 | 建模与编辑要求 |
| --- | --- |
| 前 C 环、后 C 环 | 各自独立；不并入保险杠。孔洞保留；选配改变为非车漆材质时按实际配置控制可编辑性 |
| 前保险杠、后保险杠 | 分别建部件；曲面转角可有多个展开片，不能用单一正面投影替代 |
| 左前上翼子板、右前上翼子板 | 与前下翼子板独立识别，明确上下分件接缝 |
| 左前下翼子板、右前下翼子板 | 保留独立部件、外露区域和连接关系 |
| 左前门、右前门、左后门、右后门 | 四个独立部件；只选择外露车漆，正确处理镜座、把手及窗框边界 |
| 尾翼 | 独立部件；不会因位于后背箱上方而自动接受后背箱素材 |
| 后背箱 | 一个逻辑部件，可以包含被尾灯隔开的多个外露漆面区域；尾灯本身不能涂装 |
| 左后翼子板及连体 A 柱外板 | 一个逻辑部件，覆盖用户确认的整段连体外板；允许为展开增设计算切缝 |
| 右后翼子板及连体 A 柱外板 | 与左侧对应，但独立身份、独立图案，不复用镜像重叠 UV |
| 机盖 | 保留手稿中的中央主要部件，使用实际外露轮廓 |

这里区分三个概念：

- **部件 BodyPart**：用户选择的真实部件身份。
- **漆面区域 PaintRegion**：该部件上可绘制的表面，允许不连通。例如后背箱尾灯两侧的漆面。
- **展开片 Chart**：为降低畸变而切开的计算区域。同一部件可以有多片，计算切缝不能成为虚构的实车部件。

左右后翼子板连体外板即使在 GLB 内被拆成多个 mesh，仍归入同一逻辑部件；反过来，多个实际部件即使共用一个 mesh，也必须分开标注。

当前“侧裙”等区域需要检查真实物理归属，纳入相应部件或经核验的独立项。不能为凑齐既有 19 项而保留错误命名，也不能因本轮清单未单列而丢弃外露漆面。

建议先在模型视图中完成逐部件彩色标注图，并与真实接缝对照。此环节是展开制作的输入条件，不得由材质名、包围盒或视觉近似自动宣布完成。

## 4. 2D 界面按手稿组织，提供两个编辑入口

### 整车拆开展平

整体组织采用车头朝上的布局，前保/前 C 环、机盖、后背箱、后保/后 C 环沿中央纵向排列；前翼子板、四扇门、后翼子板连体外板在两侧按实际前后关系展开。尾翼在尾部附近保留独立位置。上下前翼子板必须能分别辨认。

中央车顶/玻璃位置可作为浅色定位参考；可绘制范围由当前模型的真实车漆属性决定，不能因为手稿中有“车顶”框就把玻璃开放为车漆面。

显示真实边界、部件名称、不可涂区域和选中高亮。连体后翼子板可以显示其沿侧窗上沿延伸的狭长轮廓；若降低畸变需要切成多个展开片，选中任何一片都高亮完整部件并显示对应关系。

排版留白只服务于观察：移动展开片的位置、缩放视图或改部件间显示间距，不改变 3D 上的素材位置、大小和覆盖区域。

### 单部件编辑

通过部件列表、整车展开中的双击或 3D 点选进入。显示完整部件的全部漆面区域；后背箱被尾灯隔开的区域要一起呈现，连体后翼子板要保留整个部件的关联。

支持相同的选择、移动、缩放、旋转与撤销。跨面图层进入单部件视图后仍是原图层，可用淡色邻接预览显示超出当前部件的部分，并提示覆盖到哪些部件。

**视图范围与素材覆盖范围必须分开：**切换到单部件编辑仅改变观察范围，不自动裁掉图案。素材另有“自动跨相邻漆面 / 限定所选部件”覆盖设置；需要只修改某一个部件的片段时，应显式创建部件裁剪或解除关联，不能暗中把同一图层拆成多份。

## 5. 新的几何映射基础

### 5.1 固定一份可编辑曲面

从原模型建立独立的编辑表面数据：仅包含经核验的外露车漆三角片，保留源节点、源三角面以及裁切片段到原三角面的重心坐标关系。复制顶点以建立 UV 切缝时保留源身份，不把重排后的数组序号当作永久 triangleId。

2D 显示、3D 拾取、覆盖计算、渲染、导出均读取这份曲面。已有整车 BVH 可用于拾取遮挡与辅助审核；“某个方向能看到”只作为辅助信息，不能替代车漆语义标注。

可编辑域以已确认的静态装配姿态定义，与用户当前相机无关。部件、装配或材质切换时重选有效区域，避免每次转动视角都改变素材。

### 5.2 建立专用、无歧义的 paintUv

为每个编辑三角片保存 `partId / regionId / triangleId / chartId / paintUv`，并建立 `UV 点 → 三角面 + 重心坐标 → 3D 点` 的反查索引。合法图集内不得有不同表面互相覆盖的有效 UV 面积；接缝顶点可以有多个表示，但必须保存对应关系。

SU7 首版优先使用本地 Blender 制作经人工核验的展开资产，选择切缝并比较 Minimum Stretch、Angle Based 等展开结果。参数化优化只提供候选结果，最终仍要检查三角形翻转、重叠、拉伸和方向。不要在每次拖动时对整车重新展开。

原始材质 UV0/UV1 不覆盖；专用 paintUv 可存于独立编辑几何或 sidecar 数据，避免与原材质贴图发生耦合。

必须接受的几何边界：复杂车身不能保证整车成为一张既无切缝、又无拉伸的平面。通过合理分片、畸变提示和接缝关联实现手稿式布局，不能把它直接标为已通过实物施工验证的纸样。

### 5.3 分开三种坐标

| 坐标 | 责任 |
| --- | --- |
| 表面身份与局部坐标 | 确定素材在真实曲面上的位置、朝向、覆盖范围 |
| 部件展开坐标 | 将对应曲面画到 2D，并提供可逆拾取 |
| 界面布局坐标 | 将部件按手稿排列、留白、缩放；不参与物理尺寸计算 |

纹理打包布局可以另行优化显存占用；不能让自动打包的岛排列替代用户的整车编辑布局。

## 6. 自动跨面：一个图层，明确的曲面覆盖

### 6.1 跨面不能仅靠 UV 展开自动获得

**核心目标就是让同一素材越过一个真实漆面边界后继续出现在相邻漆面，并在 2D 与 3D 同时保持连续。**例如经标注允许连接的前门→后门、前门→前上翼子板、后翼子板→连体 A 柱外板：图案进入一侧后，覆盖计算会沿已建立的边界对应延伸到另一侧，不复制为两个可独立漂移的图层。真实门缝或钣金缝保留为空隙；两侧图案按边缘切向和核验过的对应点衔接。非漆面、被遮挡的内板、车窗、灯具始终没有覆盖片段。

这里的“自动”指用户无需手工切图和对齐，系统沿车型专属的已核验接缝连接自动派生覆盖；**不**指按二维距离把素材广播给任意邻近表面。素材越过界面中的排版留白时，仍通过曲面接缝关系连续，不把留白误认为实际车身长度或新的投影空间。整车拆开展平用于看清各部件形状，独立的接缝图用于连接实际边缘；两个部件在屏幕上相隔多远不影响其 3D 相邻关系。

独立 UV 岛之间天然存在切口，任意把矩形画在多个岛上，仍无法保证真实表面上的连续性。需要独立的边界连接表：

- 同一连续曲面上的 UV 切缝：保存两侧边段、方向和参数对应。
- 不同部件的真实相邻缝：例如前门—后门、机盖—前上翼子板。经核验后建立连接，记录真实缝宽、切向关系及允许传播方向。
- 同一部件被尾灯等隔开的区域：保留明确的构图对应关系。图案可以连续构图、分别落在两侧漆面上，灯具区域没有绘制片段。该关联不能从“同一部件”自动推导成向所有区域广播。
- 独立悬置件或无连接表面：例如尾翼与后背箱，不因距离近或在 2D 排版中靠近就自动连通。需要包覆到这些独立部件时由用户明确扩展覆盖范围。

虚拟连接只负责传递图案坐标，不增加可绘制几何，也不在门缝、车灯或玻璃上生成贴图。窄缝的实际宽度与界面排版空白是两件事。

### 6.2 图层保留来源，覆盖片段作为派生结果

建议保存的主数据：

```text
LayerPlacementV2
  layerId / sourceAssetId
  mappingVersion / modelFingerprint / paintSurfaceFingerprint
  anchor: partId + regionId + sourceTriangleId + barycentric
  tangentOrientation + referenceWidthMm + referenceHeightMm + rotation
  coveragePolicy: adjacent | selectedParts
  selectedPartIds / bridgePolicy

DerivedCoverage
  targetTriangleFragments[]
  sourceUvAtFragmentCorners[]
  chartIds[] / distortionMetrics
```

素材的 2D 矩形仍是来源图像，最终在车上形成的轮廓由真实曲面决定。`referenceWidthMm` 表示选定映射基准下的设计尺寸，不承诺所有弯曲方向都严格等长。

连续关系应由共享的表面域坐标定义，而非手稿式 2D 岛的屏幕位置：每个真实部件/展开片有独立的界面排版变换；跨缝配对的边仍共享来源图像坐标。故在展开图中，跨接缝素材可能表现为分别落在两个已排开的部件上的两个可见片段，但两片属于同一个图层、同一次变换，返回 3D 后在真实接缝处连续。需要查看连接时显示跨缝连线/对应边提示；界面空白不作为素材的几何跨度。

从锚点建立局部曲面参数域，沿真实邻接和允许的虚拟连接扩展到素材范围。按三角片计算来源图像 UV，接缝两侧共享对应的来源坐标；必要时以局部低畸变求解改善弯折。路径和切缝选择须固定，不能因查询顺序不同而旋转或镜像。

较大图案覆盖高曲率区域时，检测折叠、重叠或过大拉伸，增加计算切缝或要求调整覆盖范围；不能让局部切平面算法无限传播到整车背面。

### 6.3 2D 与 3D 如何编辑同一个图层

2D 拖动：先从界面坐标反查展开片，再得到三角面与重心坐标。通过曲面映射移动锚点/方向，重新计算受影响覆盖。穿过已连接的 UV 切缝时沿对应关系继续；不能直接将画布位移加进全车世界投影坐标。

3D 拖动：整车最近命中完成遮挡判定；命中属于可编辑曲面时取得同样的三角面与重心坐标，进入同一个编辑会话。整车 BVH 与编辑面 ID 必须关联，不能先过滤掉玻璃等遮挡物再拾取车漆。

素材的“移动到另一个部件”与“同时扩展覆盖到相邻部件”分别处理。用户把锚点拖到另一片时可重定位整个图层；覆盖扩展仍只走已许可的连接。经过界面留白时保留上一个有效锚点，显示待落点，落到有效部件再更新，避免随机跳向最近轮廓。

## 7. 渲染与同步改造

### 7.1 以覆盖片段限定绘制

最小可行路径：继续利用现有每图层纹理缓存与原生 wgpu 管线，改为绘制 `DerivedCoverage` 的受限三角片并采样其来源 UV。2D 用同一覆盖片段的展开坐标绘制，不再将整张图片简单裁到合并 Path2D。

后续可将静止图层合成到分块 paintUv 纹理，减少“每层×每部件”重复绘制；拖动层保持单独增量预览。纹理烘焙需要处理接缝 padding、mipmap 与透明边缘。该优化放在映射正确性验收之后。

保留深度测试以处理观察遮挡，但不依赖它限定素材覆盖。前方部件遮住后方部件时，后方属于该素材的正确图案可以保留；其内容不随相机改变。

### 7.2 Rust 维护一个临时编辑会话

统一 `BeginGesture / PreviewGesture / CommitGesture / CancelGesture`：

- 两端输入均进入同一个 Rust 映射服务；React 和渲染线程只消费带版本的预览结果。
- 预览带 `sessionEpoch / baseRevision / gestureId / sequence / mappingVersion`，旧包和旧会话结果直接丢弃。
- 高频移动只传锚点、变换和小量覆盖增量，源图片预上传；不逐帧传整张 RGBA。
- 计算队列采用最新输入优先，过期局部计算可取消。单个活动手势拥有变换权，另一视图实时显示结果。
- 松手只创建一次撤销记录；Esc、失焦或提交失败恢复两端共同的提交前状态。
- 更换整车/单部件视图仅改变展示；不隐式提交新变换或拆分图层。

现有 session/revision 校验、图层历史、资产摘要、模型加载、相机与 PBR 渲染可继续使用；需要替换的是映射与交互预览的核心数据，而非再次整体更换 Tauri/React/wgpu 技术栈。

## 9. 实施顺序与每阶段完成条件

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| A：分件与问题基线 | 建立真实部件彩色图；标注前上/前下翼子板、后翼子板连体 A 柱、后背箱分离漆面；记录现有误填案例 | 每个已确认部件有来源面片、轮廓和审阅图，非车漆及隐藏折边不进入编辑域 |

## 10. 必须新增的验收案例

1. **真实分件**：逐一选中用户确认的部件；左右前上/前下翼子板不可串选；后翼子板与其连体 A 柱整体高亮；后背箱多个漆面区域属于同一部件。
2. **不串面**：前门放置带文字与棋盘格的素材，转动相机检查对侧车门、内板和同方向深层表面无额外图案。验证的是覆盖面 ID 及像素结果，不能只看单一截图。
3. **跨门缝**：长斜线跨前后门，门缝留空、两侧图案接续；缝宽变化不由 2D 排版留白决定。
4. **跨朝向**：图案同时覆盖机盖与前上翼子板，无 belt/top 切换导致的方向跳变；急弯处显示畸变数据。
5. **前上/前下翼子板**：分别编辑及允许范围内联动；检验实际分件缝与轮拱孔洞。
6. **连体后翼子板**：图案从后翼子板沿同一外板延伸到侧窗上沿/A 柱段，跨计算切缝保持同一图层，不误填车窗。
7. **后背箱被尾灯隔开**：一个图层可按已确认构图关系作用于多个漆面区域，灯具区域始终无覆盖片段；不意外附着到尾翼。
8. **C 环和保险杠**：分别选择，孔洞不填充，前后及相邻深度面不被一起投射。
9. **两种 2D 模式**：整车放置、单部件修改、返回整车与 3D，layerId、覆盖与尺度一致；单部件视图不能隐式裁剪跨面图层。
10. **拖动与历史**：2D→3D、3D→2D 在拖动中同步；取消两侧回退；一次手势一次撤销；存储重开后覆盖完全可复现。
11. **相机无关**：转动相机不改变素材覆盖集合；遮挡只影响当下可见性。
12. **资产与版本**：所有可编辑三角片有唯一身份；非退化区域二维反查可逆；没有意外 UV 翻转、重叠；错误版本不能静默套用。

建议第一轮量化目标：已配对计算切缝两侧来源 UV 误差不超过所选验收分辨率的 1 个纹素；2D→3D→2D 往返误差控制在 1 个屏幕像素内；在明确记录硬件、视口、素材分辨率和图层数的代表性工程上，双端预览端到端 P95 小于 50 ms。门缝两侧需扣除真实空隙按连接定义比较，不能把两条实物边强行视为同一点。

展开畸变另按每三角片局部映射的长度/面积变化统计，至少给出分位数、最大值和热图。具体拉伸门槛应在两组代表曲面原型后确定；显示 mm 不等于已经满足实物裁切精度。

## 11. 兼容与资料依据

新工程使用新的映射版本。旧投影工程保留可识别的旧映射模式；转换时生成副本，按旧公式在已确认目标曲面上重建来源 UV，输出前后对照。旧工程原本的重复投射不能无损还原为用户的真实意图，需标出受影响图层，不能宣称自动转换必然正确。

本地依据：当前 NEXT 源码、现有跨面/遮挡修复记录、`next/.reports/smoke-1794290338412` 的既有报告及截图、本轮 GLB 属性只读检查。既有 smoke 的通过记录不代表本方案已实现，也不覆盖新的物理分件、真实展开和双端实时预览要求。

算法资料采用一手来源，作为实现选型依据：

- Blender Manual：UV Unwrap 的 Angle Based、Conformal、Minimum Stretch，以及切缝和畸变说明。`https://docs.blender.org/manual/en/latest/modeling/meshes/uv/editing.html`
- CGAL Surface Mesh Parameterization：参数化、切缝与 ARAP 等方法的适用条件。`https://doc.cgal.org/latest/Surface_mesh_parameterization/index.html`
- xatlas 官方仓库：图表生成与打包属于独立步骤，自动图集不包含本项目的部件语义与跨缝编辑协议。`https://github.com/jpcy/xatlas`
- Schmidt 等，Decal Parameterization with Discrete Exponential Maps，SIGGRAPH 2006：局部贴花参数化参考；不能据此假设复杂整车均可用一个无畸变局部坐标域覆盖。

最终采用哪一种展开/局部参数化算法，以当前 SU7 的两组原型及复杂部件验收结果决定。应用骨架、原厂材质与独立选配逻辑可沿用；几何分件、可逆映射和覆盖协议是这轮改进的核心。
