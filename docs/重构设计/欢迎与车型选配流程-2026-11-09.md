# 欢迎与车型选配流程增量

日期：2026-11-09
实施目录：next/
视觉约束：使用软件自身的深色、绿色、卡片及面板语言；不复刻小米页面、布局、控件、导航和品牌装饰。

## 使用流程

启动 → 欢迎页。

- 新建设计 → 选择车型 → 车型选配 → 完成配置 → 工作区。
- 加载设计 → 本机 Next 设计库 → 选择已保存设计 → 工作区。
- 欢迎页显示最近三份设计；有当前会话时也可继续当前设计。
- 工作区支持返回欢迎页和新建设计。dirty 会话切换时必须保存、放弃或取消。
- 在车型与选配步骤间返回会保留本次选择。完成配置前不创建持久化工程；选择完成后创建 dirty 会话，由用户保存。

加载入口当前覆盖本机 Next 设计库，不是任意文件导入。旧 .su7design 迁移仍待阶段 4。
本轮以前创建的无车型草稿仍能从设计库打开和保存。

## 页面

欢迎页：新建、加载、最近设计与软件自己的车辆形态示意。
车型页：七张车型卡片，按轿车、SUV、多功能车型筛选；选择后继续。
选配页：设计名称、配置摘要、车漆/轮毂/内饰/方向盘四个分类。
配置完成后工作区属性栏显示车型及四项选配。
设置入口在所有页面保持可用。

车型插图由软件本地 SVG 绘制，只表达形态；不是对应车型的精确模型或材质预览。
本轮没有复制官方页面截图、调用小米 UI、加载 iframe、增加业务 HTTP，或执行旧引擎。
选配当前是结构化工程数据，不会伪造实时 3D 加载或材质切换。

## 车型目录

next/tools/build-vehicle-catalog.mjs 从本地 backend-adapter.json 的配置数据提取四类选配；
输出 next/catalog/vehicles.json，运行时由 Rust 静态嵌入。
发行运行不依赖旧目录；前端从 Rust View 接收目录，不自行读取旧文件。
目录仅保留稳定 ID、名称、色块、四类内互斥信息、默认组合和源文件 SHA-256。
没有远程 URL、请求头、业务页面、脚本、价格或下单逻辑。

缺少独立方向盘数据的车型使用 factory / 保留原车配置，并在页面说明。
方向盘原始数据包含 defaultSsuNode 的，也提取真实默认选项。
级联车轮数据提取具体 SSU 子项，而非只保存无法关联的父级显示名称。
默认组合从可用组合中选择，尽量匹配原始 defaultSelect，同时保证四类互斥校验通过。

目录是本地捕获配置快照，不代表实时销售清单，也不是完整商业选装规则引擎。
只校验本轮四类内的已记录互斥；未接入其他套装、车型版本联动、价格和库存逻辑。
catalogVersion 当前固定为 1。后续更换目录需保留旧版本映射，不能直接删除已存工程使用的 ID。

## Rust 状态与兼容

新增 create-configured 操作，只有车型及完整选配校验成功后才创建会话：

    {
      type: "create-configured",
      name: string,
      vehicleId: string,
      configuration: {
        catalogVersion: 1,
        paint: string,
        wheels: string,
        interior: string,
        steering: string
      }
    }

Rust 校验车型存在、目录版本、各项所属类别与车型、组合互斥、工程名称及当前 dirty 保护。
无效创建不会替换当前工程。
ProjectDocument 和 ProjectSnapshot 增加 configuration，ProjectSummary 增加 vehicleId。
保存后重开恢复原始 ID 与配置；重命名/撤销不会覆盖配置。
配置为空时序列化省略字段，从而保留早期无车型草稿的文档摘要校验兼容性。
有 vehicleId 无 configuration 或反过来的不完整文档均拒绝。

仍为阶段 1 的内部 JSON 草稿存储，不宣称完成便携 v2、模型加载、车型编辑或导出。
当前配置在新建时确定，工作区只读显示；后续配置变更应纳入文档事务与撤销系统。
