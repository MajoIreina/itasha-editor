## 1. 存储形式决策

本稿采用两种形态：用户工作目录保存 content-addressed blobs + 版本化 manifest；可携带的 `.su7design` v2 为 ZIP 容器，包含 `manifest.json`、`project.json` 和被引用 assets。格式由 ZIP signature 与 manifest 内 `format/containerVersion/documentVersion` 识别，不再叠加自创前置二进制头。

```text
工作目录（应用管理，增量保存）         便携文件（ZIP，显式导出/另存为）
projects/<project-id>/                 manifest.json
  HEAD.json                           project.json
  revisions/<revision>.json           assets/<sha256>.<codec>
blobs/<sha256>.<codec>                 previews/（可选）
recovery/<project-id>/                 cache/（可选，可丢弃）
```

内部 commit 先持久化新增 blobs，再落 immutable revision，最后原子替换 HEAD。这样大素材未变化时不用每次重打 ZIP。首次导入/便携保存仍需写全部引用数据，不能套用仅 metadata 保存耗时。

用户打开外部文件后导入应用工作目录、保留 sourceRef；“保存”保存工作目录，“另存为/导出工程”写便携文件。若产品要求 Ctrl+S 原位更新外部文件，需要额外的绑定文件模式与覆盖提示，不能在此初稿中偷偷混用两种语义。首页最近工程显示工作副本与来源，避免用户误以为外部文件已经更新。

manifest 列出 blob hash、长度、codec、像素尺寸和 model references。车型模型默认按 fingerprint 外部引用，不随每个工程复制；用户选择打包模型且该包可携带时才写入独立 entry，标清体积。工程导入缺模型时仍保留用户素材和设计数据，提供受限编辑/重新关联，不静默换车。

## 2. v1 迁移

识别当前 `format=su7-livery, version=1` JSON，先解析到 legacy DTO，再经纯迁移步骤形成 v2；旧文件不原位改写。

1. 校验文件总字节、图像解码尺寸、layer/patch/face 数、NaN/Infinity 和数组长度关系；旧 wrap version 与 coverageVersion 单独处理。
2. 解出 assets 的 data URL 原始字节、MIME、原名和尺寸，按内容 hash 去重；不为减小包而擅自二次有损编码。
3. 根据旧 vehicle/configuration 和捕获版本定位 model fingerprint。转换时保留旧 mesh/primitive/triangle 到 canonical geometry 的映射；已做重排/简化却无 remap 时禁止用原 face index。
4. 旧五向像素→旧车型物理范围→新 SurfaceProfile 坐标；保存 sourceUnits/sourceProfileVersion，制作校准宽高与 bleed 参数原样迁移。
5. 用 remap 重建锚点和投影，比较原轮廓/UV；无法匹配时标 `needs-rebind` 并保存 legacy 数据供恢复，不能丢弃整层。
6. 完整验证并准备 previews 后才原子替换当前 session。失败时当前项目仍打开；任务 staging bytes 释放。
7. 输出迁移报告：source hash、migrator/adapter 版本、每层结果、需用户处理的问题。首次另存为 v2 写新文件；覆盖源需用户明确选择。

mesh 重排、合并、LOD 和 tangent 生成对索引的影响必须在阶段 0/2 建立 remap，不能到读旧工程时才发现映射缺失。显示 LOD 与编辑 canonical geometry 分离。

## 3. 并发保存、原子性与恢复

`project_save(sessionEpoch, expectedRevision, requestId)` 捕获 Rust authoritative immutable snapshot，前端不传全量 document/patch。命令校验版本后返回 taskId；后续编辑可以继续，写完返回本次 savedRevision/contentId。只有 currentContentId 等于 savedContentId 才显示 clean。

同项目存储 actor 串行推进 HEAD，不允许旧 revision 在新 revision 后覆盖。autosave 只合并尚未开始的 autosave 请求；显式保存任务保留独立结果语义，若合并必须告知实际保存 revision。新工程切换后旧保存可安全完成在旧项目目录，不能发事件清除新项目 dirty。

Windows 实现采用同卷临时文件 + flush/sync + 支持覆盖的替换操作；单纯假定跨平台 rename 都能覆盖现有文件不成立。断电持久性须由实现及文件系统故障测试确认，原子可见不等于硬件断电保证。

HEAD 更新成功前保留前一个有效 HEAD 与 revision。恢复扫描仅引用已完成 hash 验证的 blobs；未引用 staging 文件可清理。保存失败（磁盘满、权限、占用、同步失败）保持 dirty 并返回 `io-error`，旧完整存档必须可重开。

工作目录、history 和进行中的 export/save 都会持有 blob 引用。GC 使用保留的 revision/checkpoint/history/task 引用集合；不能在删除 layer 后立刻删除仍被 undo 使用的素材。

## 4. 关闭生命周期

`Running → ClosingRequested → GestureCancelled → SavePending → ResourcesStopping → Closed`。Rust 拦截 native close；React 弹窗提供保存/放弃/取消。WebView 失去响应时由 Rust 提供原生降级选择与最近提交内容恢复，不能依赖执行 JS 才能取到唯一工程副本。

保存成功后取消后台任务、停止渲染提交、等待受限时间的 GPU/IO 清理、释放 surface，最后销毁 native host/WebView。保存失败回到 Running 并显示错误；进程强杀依靠最近 recovery，不能宣称未提交 preview 也可恢复。

## 5. 图片与资源

Rust 文件 picker 或 native drop 创建 FileGrant，UI 用 opaque token 请求导入；选中的外部路径可以在授权范围内读取，内部 AssetRef 指向应用 blob 仓库。导出目录同样经 picker grant，不能把所有有效用户目录限制为 app root。

图像管线保留原始源，按能力处理 EXIF/ICC/alpha/多帧。阶段 1 不缩减旧版支持格式清单；阶段 4 给出每种格式的替代 decoder/sidecar 与测试状态，无法支持的格式显式报错。SVG 文本/图像引用需受限处理，不能把外部 URI带入 renderer。

缩略图、编辑预览、制作源分别计费。UI 获取缩略图二进制后生成/回收 Blob URL；大模型/纹理 Native 直接由 Rust reader 读取，不过 WebView。导入取消应释放任务 staging，不撤销已明确提交的其他素材；批量导入返回每项状态。

## 6. 导出流水线

导出捕获 committed revision，关闭选择/工具 overlay 的独立 render context，使用显式制作 profile；与交互低清纹理和窗口 DPR 解耦。

| 输出 | 数据来源 | 必测项目 |
| --- | --- | --- |
| 工程 v2 | snapshot + 引用 assets + 可选模型 | hash、ZIP entries、离线重新打开 |
| 2D PNG | 原始素材与 exact projection | 像素尺寸、alpha、底漆、色彩空间 |
| SVG | shape/text 描述与曲面片段 | 路径/clip、字体 fallback、转义、图像引用 |
| 制作 PNG/PDF | mm/DPI/bleed + 校准数据 | 尺寸元数据、像素上限、字体、透明度/白底规则 |
| 全车面 ZIP/UV | SurfaceProfile + canonical geometry | UV/投影 metadata、车型/算法版本、路径完整 |
| 3D 截图/离屏图 | 固定 camera/lighting 的 render target | 指定分辨率、颜色转换、无 UI、无 selection |

高分辨率渲染、PNG/PDF 编码为后台任务，GPU readback 使用异步完成通知；不为每个屏幕帧 readback。大幅面采用 tiling 或明确上限，阴影/后处理 tiling 边界要单独对照。取消发生在最终文件替换前可删除临时文件，完成替换后返回已完成。

图片/字体和表面投影的 CPU 参考路径用于比对 GPU 实现；ICC、金属漆 PBR 屏幕效果与制作 RGB 文件的差异要有一致的导出语义。投影图继续不包含实车钣金展开/施工补偿，现有实测尺寸校准提示保留。

## 7. HTTP 替换与旧模块去向

| 当前模块/路由 | 目标 | 迁移方式 |
| --- | --- | --- |
| desktop Electron 全链 | Tauri host/platform | 重建窗口、退出、单实例、运行时配置 |
| http.rs / api.rs / `__api` | typed commands/application | 删除 HTTP transport，按用例迁移纯逻辑 |
| storage.rs / settings.rs | persistence/settings service | 审核并复用校验/写入逻辑，修订并发语义 |
| images.rs / export.rs | image/export jobs | 复用格式规则，去 Base64 HTTP DTO |
| archive.rs / replay.rs | 离线转换工具 | 仅转换阶段读取存档；生产 runtime 不重放网站 |
| patches.rs / replay-sw.js / resources/custom.js | 无生产替代 | 原引擎移除后从新发行依赖图删除 |
| studio.js | React + domain/session/export | 按用例和状态迁移，不整包引入 |
| bridge.js | viewport/renderer/adapter | 私有 viewer 替换，保留功能验收场景 |
| surface-wrap / paint-projection | Rust geometry + WGSL | 搬迁数学与约束，车型特例移入 adapter |
| camera-* | Rust camera + React panel | 用现有数学 fixtures 对照 |

以后需要联网下载时由可选 Rust network service 负责；本期应用逻辑离线。Tauri/WebView 内部资源协议可能呈现 URL 形式，这不等于应用启动了业务 HTTP server；验收看监听 socket、业务依赖和实际外网请求，不能只按 URL 中出现 `http` 判失败。

## 8. 验收与回滚

| ID | 内容 | 必须留下的证据 |

| E4-05 | 20 次开关工程/模型/质量档位 | CPU/GPU/文件 handle 曲线与保留缓存说明 |
| E4-06 | 原厂漆、透明层、文字、曲面输出 | 尺寸、视觉容差、无选中效果和 UI 污染 |

旧包与旧 v1 文件留作回滚来源；v2 文件不宣称旧应用可读。正式发布前冻结支持车型、格式、图形能力与未完成项，支持范围以实际矩阵为准。来源与分发记录在发行清单中核对；文档与代码预研可继续使用自制测试模型。

## 9. 交付物
