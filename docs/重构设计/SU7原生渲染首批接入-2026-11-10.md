# SU7 原生渲染首批接入

实施日期：2026-11-10。版本：0.3.0-dev.2。阶段 0 资产验证与阶段 2 首批实现；完整 Gate 0 / 阶段 2 验收尚未完成。

## 当前交付

从欢迎页新建或打开 SU7 Max 设计后，工作区使用 Rust / wgpu 原生子窗口显示真实模型。按设计中保存的选项组装车身、单套四轮模块、单套方向盘，并替换车漆参数及内饰贴图。左键旋转、右键平移、滚轮缩放、双击或工具栏按钮复位。

保持 Win11 风格深浅主题、跟随系统、上下/左右分屏、工程库拖宽与收起、右侧模块布局。视口随布局变化调整物理像素尺寸，弹窗显示、进入 2D 视图及离开工作区时隐藏；同一会话重新显示时复用 GPU 场景。视口内的快捷键通过原生键盘事件转发到 React 的现有按键绑定。

其他车型继续保留设计流程与保存能力，但显示明确的模型未接入提示，不替用 SU7 模型。2D 画布、素材编辑、贴花、部件拾取、导出及旧工程迁移仍未实现。

## 实现边界

| 模块 | 职责 |
| --- | --- |
| crates/renderer/assets.rs | 与车型无关的静态 GLB 读取；层级变换、镜像绕序、法线、UV、索引、材质、贴图、预算与包路径验证 |
| crates/renderer/gpu.rs、studio.wgsl | GPU 资源、深度、透明排序、基础金属粗糙度 / clearcoat 近似、相机、提交与 surface 恢复 |
| src-tauri/src/model_package.rs | SU7 商品 ID 到资产模块、车漆参数和内饰主题的适配；后续新增车型单独增加适配器 |
| src-tauri/src/viewport.rs | Windows 子窗口、原生输入、物理像素布局、加载任务串行合并、会话 / generation 隔离与状态发布 |
| src/NativeViewport.tsx | React 视口占位布局、状态、重试与重置；合并布局 IPC，不传逐点鼠标数据 |

GPU 在首次加载时初始化。文件读取和 PNG 解码在一个独立加载线程执行，过期排队请求合并为最新请求，完成结果由 generation 隔离；已经运行的旧解析暂不能中断，因此快速切换可能等待旧任务结束。同一会话与相同加载计划命中最近一次场景缓存。当前仅缓存一套场景，离开工作区会隐藏但保留该缓存。

生产帧直接由 Rust/wgpu 提交到原生 surface，图像不经过 JSON、IPC 或 CPU 回读。测试版仅在 `ITASHA_TEST_DATA_DIR` 下回读首帧 PNG，供检查 GPU 输出；此调试代码不编入发行版。WebView 截图本身不包含原生子窗口，因此不能用网页截图替代原生画面验证。

目前为静态 PBR 与解析式摄影棚光照近似，尚未接入原始 HDR、角度变色公式、颗粒效果、阴影、mipmap、抗锯齿、骨骼或七组开合动画；不声明与官网或 Blender 画面等价。原始厂商 JS / WASM 不参与应用运行。稳定节点/图元 ID 已保留，但尚不等同于完成规范化几何指纹或旧工程三角面映射。

当前上限为单 GLB 128 MiB、三角面 300 万、已解码纹理 512 MiB；纹理设置会影响模型重新加载，预览最长边最多 4096 px。目标帧率、渲染分辨率和缓存预算设置暂不生效，界面已明确说明。隐藏或静止时停止主动提交，不以持续空转获取帧率。

## 已验证与测量

桌面回归涵盖 SU7 两套真实配置、GPU 首次提交、会话过期拒绝、未接入车型、视图切换复用、双向分屏尺寸、设置遮挡、静止无额外提交，以及原有工程保存/撤销/重开/关闭保护。通用自制 GLB 测试覆盖层级、镜像变换、边界和来源 ID，不依赖 SU7 数据；另检查窄视口相机取景与路径越界。

测量环境：Core Ultra 7 265K，约 63.3 GiB 系统可见内存；wgpu 实际选择 NVIDIA GeForce RTX 5080 / Vulkan，驱动 32.0.16.2101。不是仅从设备列表推断 GPU。当前布局物理视口 914×436，后续也检查 497×718 窄视口布局。

第一套：靛石绿、ACAL02、砂陶米、运动方向盘，共 767,611 三角面、221 图元、37 张 GPU 纹理；所选 GLB 27,771,260 字节，解码纹理像素约 97 MiB，后者不是总显存测量。第二套：卡布里蓝、ACAL38、迷雾紫、真皮方向盘，共 771,979 三角面、221 图元。

五次热进程、热文件缓存、Debug 构建重载采样如下。运行命令：`$env:ITASHA_RENDER_BENCH='1'; node tools/smoke-desktop.mjs`。样本数量有限，p95 使用五个样本的最大值。

| 指标 | 范围 | p50 | p95 |
| --- | --- | --- | --- |
| CPU 场景就绪，含读取/解码、排队与 GPU 资源创建/上传指令 | 1,610–1,626 ms | 1,615 ms | 1,626 ms |
| 创建 GPU 资源与发出上传指令的 CPU 耗时 | 17.3–20.1 ms | 17.8 ms | 20.1 ms |
| 采样时最近一帧 CPU 编码/提交调用 | 1.45–1.97 ms | 1.49 ms | 1.97 ms |

快速切换到第二套配置的单次场景就绪记录约 2.80 秒，其中解析约 1.54 秒，其余包含等待正在执行的旧任务。这是后续任务取消优化的基线。

这些不是冷启动、GPU frame time、显示器 present 延迟或 Release 性能，也不能据此承诺 60/120 FPS。完整 60 秒轨迹、集显、100%/150%/200% DPI、多屏与设备丢失矩阵尚待完成。Windows computer-use 服务连接失败，未完成真实鼠标拖动及完整原生窗口合成截图检查；已检查 Rust GPU 回读画面与自动化原生状态/布局证据。因此 Gate 0 仍为 Conditional，保留 Native 主路线开展后续验证。

## 0.3.0-dev.3：修复 3D 区域空白

用户反馈“区域空白，但底部有三角面数量”。复现确认：GLB、材质、GPU 提交均成功，原生子窗口也处于显示状态，但被 WebView2 的同级窗口遮挡。此前的 GPU 首帧和请求尺寸检查没有覆盖真实 HWND 层级，因此未能发现该问题。

修复在每次视口显示/边界同步时使用 SetWindowPos(HWND_TOP) 将视口提升至同级窗口前方，保留 SWP_NOACTIVATE，不设置桌面置顶。设置/关闭等弹窗出现时继续隐藏原生视口。viewport_status 增加实际 nativeVisible 与 nativeFrontmost，查询时即时检查 HWND；后者在预期视口内采样 3×3 点，检查最前方子窗口是否确为 GPU 视口。

新增回归先在旧显示逻辑下复现遮挡断言失败，修复后 19 项桌面检查通过；覆盖首次加载、单独 3D、两种分屏、视图恢复、主题切换、设置弹窗隐藏与恢复。结果位于 next/.reports/smoke-1794245840033/。cargo clippy 对桌面包全部目标的警告检查通过。该检测证明原生窗口的显示及同级遮挡关系，仍不替代完整 Windows 合成截图、真实鼠标或多 DPI 验收。
