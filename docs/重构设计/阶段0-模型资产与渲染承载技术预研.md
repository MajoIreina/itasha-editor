## 1. 目的

在建设正式 renderer 或迁移 UI 前，验证重构的两项关键假设：

1. 可获得可独立载入、可用于本项目的车身网格与材质数据，不再依赖小米配置器 iframe、`plugin3D` 运行时和 `patches.rs` 注入。
2. 目标视口可与 Tauri React 外壳在一个可用的 Windows 工作区内协同，支持 resize、高 DPI、焦点、键鼠、拖放和稳定帧循环。

此阶段实现隔离的技术原型并保存可复跑记录。对已有本地资源的只读盘点、独立转换验证、自制 fixture 和 Tauri shell 可以继续推进；资产与窗口技术结论未形成前，不冻结 SU7 正式导入协议和产品 renderer 集成路线。

## 2. 现状与假设

本地资源 manifest 记录 `assets.mi`、`wasm_crypto_bg.wasm`、Draco decoder、Basis transcoder 及捕获的业务响应。可用性、许可、格式承诺和独立解码权未在代码中定义。`vehicles/su7/backend-adapter.json` 记录配置器响应和材质覆盖配置，不等同于可直接导入 renderer 的标准化材质纹理。当前没有已纳入源码的标准 SU7 glTF/GLB 文件。

待验证假设：

- 产品方可取得或合法生成稳定、可离线发行的模型包。
- 输出至少含车身 mesh、节点/部件命名、UV、表面法线、PBR 基础材质和贴图引用。
- renderer 可以在关窗/切车时释放显存资源；OS 缓存和 GPU upload 可被区分测量。
- Tauri UI 与 viewport 可以维持现有分栏/覆盖交互；不存在必须将整个应用独立成第二窗口的 UX 限制。

## 3. 实验 A：资产独立化与材质等价

### 3.1 盘点步骤

1. 生成 manifest 的唯一资源清单，记录 URL 类别、文件大小、sha256、MIME、重复内容和版本；报告中不得写入会话令牌、用户工程或个人资料。
2. 单独标识模型容器、解码器、纹理、环境图、配置 JSON 和捕获 HTML/JS；用文件签名识别，不从扩展名推断内容。
3. 沿用原资源来源与用途记录，分发范围作为发行检查项；不把来源记录缺口扩展为停止本地只读分析或自制模型预研的要求。
4. 优先验证已有加载链能否导出稳定的网格、纹理、材质参数和拓扑 remap，或使用可取得的标准源模型。在干净测试目录里独立解析和载入，明确记录转换工具依赖；最终应用不能保留配置器运行时。解码路径未确定时报告技术缺口，不估算“必然可解密”。
5. 对标准化输出计算内容 hash、字节大小、节点/mesh/primitive/material/image 数量、顶点/三角面、UV set 与纹理尺寸。

### 3.2 标准资产验收

- 至少一份 SU7 外观配置和一份已知差异配置可离线重复加载，结果 hash 可追踪。
- 网格拓扑非空、索引在界内；位置/法线/UV 均 finite；缺失或越界数据明确失败。
- 可涂装面具有稳定 mesh/primitive 语义 ID、UV set 和 adapter 映射，能够选取车门、机盖、翼子板等重点部件。
- 关键原厂材质颜色与涂层参数、贴图 color space 和 alpha 语义有记录。对照画面需固定相机、光照、环境和后处理。
- 原始资源、转换程序版本、配置输入和输出 hash 形成可追溯链；转换需可重复。
- 模型/贴图没有私有工程或配置器 HTML 运行依赖。
- 转换保持源 mesh/primitive/triangle 映射；需要重排/简化时输出 remap，保证 v1 工程的 face anchor 可以迁移。
- 纹理和材质参数可保留，但旧引擎 shader、环境反射、色调映射不能当成“材质文件”直接复用。盘点 clearcoat、金属颗粒、玻璃、特殊透明和 AO 所需表达，给出自有 shader 的等价性缺口。

如果只能拿到没有 UV/部件语义的静态网格，可以将其用于 renderer 视觉 spike，但不能据此通过“涂装模型资产 Gate”。

## 4. 实验 B：viewport 承载路线

比较下列最小 spike：

| 路线 | 内容 | 评审点 |
| --- | --- | --- |
| A：Native viewport | Tauri 主窗内 React 布局 + 由 Rust/wgpu 绘制的独立 native view/surface | 同窗裁切/叠放、DPI、resize、窗口状态、焦点、Tab 次序、指针捕获、拖放、截图、GPU 设备丢失 |
| B：React WebView renderer | 同一窗口使用自有 WebGPU canvas；Rust 保留项目/资产/几何核心 | Tauri WebView 的 adapter 能力、DOM 叠层、图形 API 降级、IPC 与 canvas 资源传输 |

测试窗口包含 React 控件覆盖视口、视口边缘 splitter、modal、缩放、最大化/恢复、双屏不同 DPI、拖动素材到视口、菜单键盘导航。对比闪烁、空白边界、错位、输入丢失、重绘和窗口销毁后的资源回收。

### 4.1 统一 spike 场景

- 一辆测试车和一个独立小型标准 glTF 网格；相机 orbit/pan/zoom、raycast 选择、高亮 overlay。
- 透明 PBR 贴花的单张静态贴图；至少一张 2K texture。
- 1600×1000 默认窗口、720×520 最小窗口、100%/150%/200% DPI。
- 60 秒连续 orbit 与窗口 resize；确认隐藏/minimize 时停止无效循环。
- 拔出设备/模拟 renderer 初始化失败时，UI 仍启动并显示降级状态。

本 spike 不实现完整配置器、阴影质量菜单、跨车身编辑、undo 或制作导出。

## 5. 采样规范

- 目标硬件记录 CPU/GPU 型号、驱动、RAM、显示器 Hz/DPI、电源模式、Tauri/WebView/renderer backend 版本。明确确认实际 adapter/设备。
- 首屏、viewport ready、asset read、parse/decode、GPU upload、首帧分别记录；冷进程、热盘缓存、renderer warm-up 分开。
- 采集至少 5 次，报告 p50/p95/max；附原始 JSON trace 与输出截图。
- 帧数据记录 CPU encode/submit 时间与 GPU frame 时间；明确 compositor present 是否可测。只记录 rAF 不能证明 GPU 已显示。
- 同一测试至少在参考独显和低配集显各跑一次；spike 有图形回退行为，不以另一块 GPU 被枚举当作 active。

阶段 0 性能检查仅回答是否具备可接受的技术路线，不要求实现最终目标值。Spike 场景的参考门槛：viewport 首帧参考机 ≤2 s（不含外部资源授权/转换）；持续 orbit 60 Hz 参考机 p95 帧间隔 ≤20 ms，低配机 ≤33 ms；窗口交互不得出现持续空白/错位；冷载/显存数值提供实际基线。超出时先记录 profiling 结果，不能用未验证的以后优化作为通过理由。

## 6. 产物与代码边界

建议放在隔离的临时 spike workspace，产品化前不与当前桌面程序耦合。提交这些产物供复审：

- `asset-inventory.json`：资源类别、大小/hash、模型统计；不得含 token。
- `asset-source-and-license.md`：来源、使用/转换/发行授权责任记录。
- `viewport-spike/`：启动脚本、锁文件、最小模型和 README。
- `viewport-matrix.json`：窗口/DPI/输入/帧时间数据。
- ADR：选定 Native 或 WebGPU route、备选失败原因、剩余限制和负责人。
- `phase0-decision.md`：Gate 结果、问题清单、估算更新和下一阶段开放范围。

提交的公共 fixture 使用自制或可随源码分发的资产；已有车型本地验证资源仍留在独立资源目录，发行包资源清单在阶段 4 核对。

## 7. Gate 0 决议

| 决议 | 条件 | 后续动作 |
| --- | --- | --- |
| Go: Native | 自制/目标资产可独立载入；native view 的同窗/焦点/缩放行为通过矩阵 | 阶段 1 固定 native view host API，阶段 2 走 wgpu；SU7 另记录资产状态 |
| Go: WebGPU | Native 集成存在实证阻断；WebGPU canvas 通过目标 WebView 矩阵 | 记录主路线变更后再实施，Rust Core 仍拥有项目/几何/资源 |
| Conditional | renderer 可跑但 SU7 独立资产或材质等价尚未确定 | 继续 shell/通用模型实现；不标记 SU7 接入完成 |
| No-Go | 两条 viewport 路线均不能满足同窗 UX | 提交技术 blocker 与替代设计；保留无依赖的工程/契约工作 |

Gate 通过由项目指定负责人记录技术证据与决策即可；不预设必须配置三个独立审批角色。来源/分发范围随发行单独检查。
