## 决策级别与适用顺序

用户已确定 Rust 主框架、Tauri、React/TypeScript、移除小米 iframe/业务 HTTP、尽量保留外壳和支持其他车模。Native wgpu、包格式、工作副本保存语义和具体 UI store 属于本稿提案，尚未实现验证。

跨阶段契约以附录 A 为准；性能测量和 Gate 口径以附录 B 为准；阶段文件补充具体实现任务。相对上位方案，本稿将“加载时间”“每帧处理时间”和“输入到显示”拆开，也明确区分增量工作目录保存与便携文件打包，不能沿用旧模糊指标直接计算加速比。本稿命令、文件格式和阈值是目标设计，已实现子集与当前接口差异见实施记录。

## 目录与变更管理

正式新代码已进入仓库内独立 `next/` workspace（已创建，见实施记录），开发过程中保留现有 app/backend/desktop 作为兼容对照；根启动入口在阶段 4 发布门通过后切换。阶段 1 的 `src-tauri/`、`src/` 均相对 `next/`。模型/运行数据不随代码复制；spike 在 `next/spikes/` 或独立临时目录，只有自制 fixture 可直接提交。

每次 Gate 记录版本、commit、测试命令、硬件、fixture hash、结果与未完成项。Gate 是技术验收条件，不是每次工具操作的审批要求。可以并行推进与未解决项无依赖的设计、代码和自制模型测试；切换 renderer 主路线、破坏旧工程兼容或改变保存交互时记录架构决策。

## 跨阶段约定

- Rust 保存并校验持久化领域状态。React 只保存交互视图和可丢弃的 UI read model；拖动预览可以在 viewport 内临时存在，不进入保存状态，直到 commit。
- 前端运行时无业务 HTTP、无 localhost API、无 Service Worker 资源重放。所有应用操作经 Tauri command/channel，静态 UI 资源由 Tauri 应用资源机制装载。开发时 Vite 服务仅用于本地开发，不进入发行运行链路。
- 高频 pointermove 在 viewport 内处理，不逐点过 IPC。跨进程/边界提交采用版本化、可校验的语义 DTO；大图和几何使用二进制协议或文件资源句柄，不使用 Base64 JSON。
- 模型和项目中使用稳定语义 ID。数组顺序、显示名称、GPU handle、进程地址、renderer object ID 均不能作为长期持久化键。
- 视口 renderer、车型适配、几何算法、素材、工程格式都有独立版本和错误报告。按车型逐一开放，不能用“模型显示成功”代替编辑验收。
- 每阶段退出条件必须由可复跑测试或验收记录证明；性能目标通过同设备同 workload 的基线和 trace 核实。
