# 整车展开排布与缺面恢复

## 问题与依据

用户截图暴露了两个不同问题：整车画布仍在逐行堆叠自动打包的 UV 岛，没有按车头朝上的手稿组织；旧的外露面候选本身也不完整。不能用部件数量或 UV 无重叠测试代替外露漆面完整性验收。

`surface.rs` 旧候选生成流程使用相对整车中心的法线阈值提前排除面片，该条件会漏掉实际外露的翻边和曲面边缘。只读原模型、默认轮组装配与 73 个外部相机采样的对照工具位于 `next/tools/assets/audit-paint-completeness.py`。采样报告指出约 0.30 m² 的原车漆面没有完整进入旧编辑面；这是采样证据，不是整车语义核准。

## 排布修正

`src/features/editor/wholeLayout.ts` 将前 C 环、前保险杠、机盖、尾厢、尾翼和后部件置于中央纵向；四门分列玻璃定位区两侧；后翼子板及连体立柱位于四门外侧；上下前翼子板独立显示。玻璃仅为不可绘制的定位参考。所有加载的部件都保留标签，其他车型新增的未识别部件也不会被静默丢弃。

排版偏移只用于显示和指针坐标的正反变换，不作为素材跨缝传播距离。`tools/tests/test-whole-layout.mjs` 检查所有部件保留、中央与左右关系和部件边界不重叠。

## 展开方向修正

`tools/assets/orient-paint-charts.py` 对独立的内在 UV 岛施加刚性旋转和平移，用源模型的前后、上下方向恢复易读布局。它不把曲面重新投影为平面，也不改原始 GLB、材质 UV、源三角面身份、三维坐标或重心对应。重排后重新封装指纹，再执行 UV 重叠与回查检查。`su7-v2-oriented` 保留了旧资产的 139,017 个编辑三角片，不能据此声称补齐了旧输入的缺面。

## 缺失片段恢复

`tools/assets/recover-exterior-paint.py` 先在源三角面的重心坐标域扣除已存在的片段，再对剩余域做外部可见性采样与边界细分；避免整块放开包围盒，也避免重复添加已覆盖面。只有已有明确所属部件的源面或来源组件进入恢复候选。无法明确归属的边缘保留在 `unresolvedFaces`，不会自动伪装成完整部件。

新的候选必须重新展开、重新封装、验证 UV 重叠和源几何回查，并在桌面中核对。源 GLB 和先前展开目录保持原样。Blender 对很小的裁切片段可能无法展开；工具须保留其内在三角片作为独立计算片，不能通过丢面绕过验收。

## 已知边界

- 左右侧裙旧候选面积约 0.00068 / 0.00186 m²，不能作为完整外观侧裙验收依据。源模型同时含大面积黑色塑料下包围；不能把它们直接开放为车漆来凑齐画布。
- 外部相机采样不能代替完整语义核准，也不能证明所有狭窄缝隙均无遗漏。
- 新展开指纹与旧候选不同；遵循用户“不需要旧工程兼容”的要求，不自动改写已有工程。
- 排布验证、几何恢复验证和施工展开精度是不同结论；不得混称已完成整车施工级纸样。
