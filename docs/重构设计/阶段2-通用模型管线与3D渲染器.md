## 1. 目标和非目标

交付不依赖小米 iframe 的车辆视口：可打开标准模型、载入场景、显示网格和 PBR 基础材质、切换环境/相机、拾取语义部件、显示选择状态，并在资源切换和窗口 resize 后正常恢复。实现独立 Vehicle Adapter，让两种显著不同拓扑模型走同一 renderer。

本阶段不实现完整曲面设计工具、素材拖拽投影、制作输出和所有车型。先用可发行的 fixture glTF 建成渲染路径；SU7 接入只在阶段 0 资产门通过后进行。

## 2. crate 职责

```text
vehicle_format   manifest schema / stable IDs / validation errors
asset_pipeline   package IO / glTF parse / texture decode / normalization
geometry         CPU scene data / BVH / semantic surface index / job API
renderer_api     backend-independent scene/camera/material resource handles
renderer_wgpu    wgpu device/surface / render passes / uploads / readback
vehicle_adapter  model IDs -> paintable part/surface tags + variant mapping
tauri_viewport   chosen Gate 0 view host / window input and resize adapter
```

`geometry` 只处理普通 Rust CPU 数据；不得持有 wgpu handle。`renderer_api` 对上暴露 typed operations，禁止在 React command 内传递 renderer object ID 以外的内部指针。持久化只使用 `VehicleId`、`PartSemanticId`、`SurfaceId` 和 model fingerprint。

## 3. 车型包规范 v1

示意清单至少记录 `schemaVersion`、稳定 `vehicleId`、显示名、来源/许可引用、坐标系/up/forward、长度单位、主模型 URI/hash/fingerprint、surface map URI 和 adapter version。导入顺序不能决定持久化 ID。

输入模型推荐 GLB/glTF 2.0；内部 loader 将资源归一到统一坐标/单位及 metallic-roughness PBR。车包保留 source node/mesh 索引，另附不依赖导入顺序的语义 ID。对没有语义 adapter 的模型可以 `displayOnly` 载入，不开放跨缝投影。

内部约定右手系、米、+Y 向上、车辆前方 -Z、车辆右方 +X；源模型朝向由 manifest 显式给出，导入一次转换。负 determinant/非均匀 scale 必须修正 winding、normal 与 tangent handedness；旧 SU7 特定方向不继续写入通用投影公式。

第一批必须支持静态 triangle mesh、metallic-roughness、base/normal/AO/emissive、alpha OPAQUE/MASK/BLEND、doubleSided 和多 UV；Draco/KTX2、clearcoat、transmission 等按资源盘点列为 required/optional 扩展。未知 required extension 失败，未知 optional extension 给诊断并按规范降级。若 SU7 依赖特殊车漆/玻璃 shader，必须实现自有 profile 并通过视觉对照才能宣称材质迁移完成。蒙皮、任意 DCC 文件和 CAD 格式首期不默认为支持，刚性车门层级动画由 adapter 定义。

`paintSurfaces` 定义：

- `surfaceId`、mesh/primitive stable key、`partSemanticId`、可涂装标记。
- topology fingerprint、UV set、local/world transform 约定和 valid UV range。
- 邻接 seam：两侧 surface、对应 edge/vertex mapping、位置与法线容差、允许投影方向。
- 材质覆盖策略：可着色的 material slots、factory base 参数、roughness/metalness/clearcoat profile。
- 可选 variant group 与 model fingerprint；variant 改拓扑必须有自己的 surface map。

导入器校验资源引用、文件 size、节点循环、数值 finite、buffer 边界、索引区间、primitive mode、UV set、法线/切线缺失策略、贴图像素预算和可见单位 bounds。失败输出 `ModelImportDiagnostic`，包含稳定 rule code、node/primitive 路径和修复建议。未经校验的三角索引不送进 renderer 或 project。

## 4. 场景与 renderer 数据契约

### 核心数据

- `SceneId`：一次载入的 runtime scene。
- `MeshKey = (ModelFingerprint, StableNodeId, StablePrimitiveId)`。
- `MaterialKey = ModelFingerprint + stable material id + variant`。
- `PaintSurfaceKey = SurfaceId`，映射到一个或多个 `MeshKey`。
- `RenderHandle`：运行期 opaque generation id，丢弃时增加 generation，禁止入工程。
- CPU 几何 buffer 使用不可变共享数据；几何修改以 revision 产生新 buffer 或范围 patch。GPU 更新使用 staging 路径，由 renderer 决定。

### Renderer API（概念）

```text
create_viewport(config) -> ViewportHandle
load_scene(asset_handle, vehicle_adapter, generation) -> TaskId
set_camera(viewport, CameraPose, revision)
resize_viewport(viewport, PhysicalSize, scale_factor)
pick(viewport, PointerRay, scene_revision) -> Option<HitRecord>
apply_material_override(surface_id, MaterialOverride, revision)
update_overlay(OverlayPatch, revision)
request_frame(viewport, RenderReason)
release_scene(scene_id)
get_diagnostics(viewport) -> RendererDiagnostics
```

IPC 只运送适合的控制/确认值。高频 raycast 与 camera gesture 在 Native viewport 内处理；最终 `HitRecord` 用稳定语义 key + primitive key + triangle/barycentric/position/normal，并包含 model fingerprint 和 scene revision。结果与当前 generation 不符时丢弃。

首选 Native 路线中 GPU 由 Rust renderer 持有。WebGPU 备选路线的执行线程/传输预算必须单独形成 ADR，本稿中的 in-process buffer handle 不能直接跨 WebView 使用。相机模块保留现有 FOV、显式 fit/focus/reset 和构图补偿数学；相机旋转/resize 不隐式重新 fit。

### 渲染 pass

1. Scene prep：transform update、可见集合、LOD 与 view frustum。
2. Opaque PBR：base color、metallic/roughness、normal/AO/emissive 的明确线性色彩路径。
3. Transparent artwork：排序/透明策略统一，写深度策略固定测试。
4. Selection/pick overlay：深度偏移/屏幕空间 outline；不更改原模型材质定义。
5. UI composition：由 Gate 0 viewport host 决定 WebView overlay/native order。

先实现单一视图、可配置 MSAA/offscreen size、方向轴；环境图/车漆 clearcoat 和高质量阴影分阶段添加。相机和编辑状态不依赖私有模型 viewer。

## 5. 模型/纹理加载流水线

```text
Rust picker / AssetRef
 -> package manifest parse
 -> size + hash + permission checks
 -> container decode / glTF scene parse
 -> texture decode + color-space tagging
 -> coordinate/material normalization
 -> geometry validation + BVH/index build (background task)
 -> adapter semantic mapping + surface validation
 -> GPU upload by renderer thread
 -> ready event with generation / diagnostics
```

大型 CPU parse、图像 decode、BVH build 放在有界 task pool；设备创建和 GPU resource mutation 由 renderer owner 线程串行化。取消需要检查 task generation；输入文件读取不能因 UI 关闭留下后台持有的大 buffer。分阶段释放 source bytes，保留可按需重读的 asset handle。

纹理缓存键包括 content hash、格式、色彩空间、mip/normal-map 选项和 renderer generation。缓存有显存字节预算与 LRU/ref-count；淘汰时确保没有 live material 引用。设备丢失后重建可重建资源，不把 GPU handle 写入项目。

Surface 未配置/尺寸为零时不 acquire frame；resize 合并，停止向旧 surface 提交后再配置新尺寸。device-lost 使全部 GPU handles 失效并尝试有限次数重建，失败进入仅编辑状态。WebView GPU 与 Native GPU 是两套运行时，设置面板分别显示其状态；不能把 Tauri UI 硬件加速关闭等同 Native GPU 已关闭，也不能保证有可用软件 3D fallback。

## 6. Vehicle Adapter

Adapter 是声明性数据优先，不写 renderer-specific 代码：

- model fingerprint allowlist。
- stable node/primitive -> semantic part/surface mapping。
- 配置 variant -> model fingerprint/manifest。
- 轮毂/车门等交互部件的编辑模式权限/可动范围。
- paintable material slots、factory palette/clearcoat defaults。
- seam graph 和每个 surface 的 UV/投影 profile。

确需特殊几何清理时，使用版本化 adapter migration function，单独测并记录，不向通用 renderer 添加车型 ID 特判。Su7Ultra 不同机盖样式用分 variant 的 fingerprint 和 seam map。

自有 `VehicleConfiguration` 用 option groups、stable option IDs、material/node variants 和约束规则表示车漆/轮毂/套件。选项先在 Rust 解析成完整有效组合，资源准备成功再原子切换；失败恢复之前组合，不能混用一半新网格和旧材质。配置 UI 由 React 实现，不复制商城价格、购物车或网络 SKU 接口为运行依赖。配置态允许 adapter 声明的部件开合，编辑态关闭该交互；保存锚点使用参考姿态。

LOD 只用于显示，拾取和贴花绑定使用 canonical geometry 或经验证的 remap。模型优化阶段不得丢失 v1→canonical primitive/triangle 映射；draw-call 合批也不能抹掉语义部件 ID。

## 7. 帧调度和性能目标

- 仅在 camera/input/geometry/material/window dirty 时请求新帧；动画部件可申请连续帧并有明确停止条件。
- pointer gesture 更新优先使用已有 BVH 与稳定资源，仅上传变化的少量 instance/UV buffer。全场景重建不得置于变换热路径。
- 参考 workload 与硬件依上位方案；实际模型三角形/draw calls 在 Gate 0 统计后校正。renderer diagnostics 输出 adapter、backend、frame CPU/GPU（可用时）、draw calls、可见三角形、texture/geometry bytes、资源代数和丢帧计数。
- 阶段目标：模型 viewport ready 参考机 1.2–3.0 s；低配 3.0–7.0 s；稳定 orbit 帧间隔 P95 参考机 ≤16.7 ms、低配 ≤33 ms。缺少硬件计时支持时标记 unavailable，不能以 CPU submit 时间冒充 GPU frame。

## 8. 验收矩阵

- 至少两种不同节点结构与不同 UV 布局的模型可用同 renderer 载入。
- 坐标轴和单位对照 fixture 的 bbox、已知顶点和 camera front/top/side 视图。
- material fixture 覆盖 sRGB/base color、线性 roughness/metallic、透明贴图和法线纹理。
- 车身语义拾取命中 stable `SurfaceId`；隐藏/不可拾取 overlay 不遮蔽目标。
- 多次载车/卸车、窗口 resize、最小化恢复、DPI 切换后无资源代数错误和持续内存增长。
- 不支持贴图压缩/设备的环境显示降级原因，仍能浏览模型或进入仅编辑能力。
- 新架构中没有外部配置器 URL、iframe、Service Worker replay 或 engine signature patch。
