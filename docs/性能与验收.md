# 性能与验收

## 实测方法

使用真实打包的 Electron + release Rust，1600×1000 窗口、中画质、独立临时工程。性能测试包含原生解码 4096×2048 图片、实际 Su7 跨部件素材、45 次输入采样、35 次曲面重算。机器为 Intel Core Ultra 7 265K、约 64 GB 内存；显卡、进程内存与原始采样见 JSON 报告。

“事件到下一帧”是输入事件到处理该次变更的下一次 rAF 回调，不是硬件鼠标到显示器像素的完整延迟。同步记录帧间隔，避免只报告快速事件回调而漏掉长时间停顿。首次模型加载使用新的应用浏览器配置，系统文件缓存未清空，不能称为冷磁盘启动。

## 本轮结果

| 操作 | 结果 |
| --- | --- |
| 启动到首页 | 约 0.63 秒 |
| 首次加载 Su7 模型 | 约 3.8 秒 |
| 4K 图片生成、原生导入与预览 | 约 2.6 秒 |
| 普通平面素材拖动 | 95% 事件到下一帧约 0.4 毫秒 |
| 实车跨面素材拖动 | 中位约 24 毫秒，95% 约 30 毫秒 |
| 跨面拖动帧间隔 | 95% 约 30 毫秒 |
| 曲面坐标重算 | 95% 约 16 毫秒 |
| 保存测试工程 | 约 0.5 秒 |

结果会随 GPU、窗口、画质、素材、图层数与后台任务变化。高画质和大工程尚不能按这组数值承诺；本轮没有在所有低配电脑上验证。完整数据以 `tools/acceptance/performance/verification.json` 最新运行记录为准。

最初仅隐藏窗口的测量被 Windows 合成器降到 1 Hz，`baseline.json` 的拖动帧间隔不能当作用户前台体验。随后在正常合成器计时下，单靠 Canvas 裁剪优化仍测得跨面拖动 P95 约 334 毫秒；GPU 批量预览降至约 30 毫秒。完整 Canvas 输出保留较慢的独立高质量路径，不把实时预览速度当作制作导出速度。

## 性能约束

`node tools/benchmark-performance.cjs --enforce` 在参考机器上执行门槛：平面拖动 P95 50 ms、曲面拖动与帧间隔 P95 100 ms、曲面重算 P95 50 ms、测试工程保存 1 秒、4K 导入 5 秒、模型首次加载 15 秒。超过即失败，不能只打印结果当作通过。

交互时合并指针更新；同一 wrap 不重复完整 JSON 比较；拓扑不变复用网格；GPU 一次批量绘制曲面三角形；图片与遮罩缓存有上限。仅编辑模式卸载 3D 并释放额外 GPU 预览资源。图片解码位于独立原生进程，经 Rust 并发门控；保存队列在排队前捕获一次序列化快照。

## 功能与曲面检查

本轮通过：Rust 单元测试 2 项、宿主配置测试 2 项、后端接口/图片/输出 51 项、真实 Electron 全链路 17 项、真实 Su7 编辑回归 49 项、解析曲面 30 项，根目录启动器 4 项，以及断开网格跨缝桥接检查。

真实车辆跨缝共享顶点 UV 最大偏差 0；充电盖目标区域覆盖 460/460 三角面。GPU 与 Canvas 覆盖交并比约 0.9983，约 1.98 万个共同不透明采样像素的平均通道误差约 0.034/255。已核对 GPU 预览截图。解析圆柱半径 0.45、0.8、1.5 的弧长与切线测试通过，保持外壳约束、不传播到内层或错误保险杠。

这些检查验证视觉曲面适配，不证明可直接裁切实车钣金。其他车型需要独立几何映射和同等验收，目前没有开放编辑。

## 2026-11-08 编辑区导入的曲面缺口修复

执行 `node tools/paint-projection-acceptance.cjs`，21 项检查通过。参考轮廓由原始车辆网格独立正交渲染生成，不依赖待测投影 UV。按用户截图中的位置、宽高构造不透明测试图案，旧法线分区算法遗漏 16,570 / 86,576 个内部采样像素（19.14%），修复后该区域遗漏为 0。检查覆盖五个方向、后门与车身部件限制、反面串图、曲面选取、网格复用、画质切换、自定义底漆，以及投影规则导出。整车和部件图层分别检查半透明红色叠加白色的像素结果（255、127、127），并验证工程 JSON 的车面键顺序变化后仍能选中实际位于上层的图案。测量允许轮廓边缘少量栅格化差异，不把它当作实车尺寸精度。

修复后的 Electron 全链路 17 项、实际编辑回归 49 项、解析曲面 30 项和跨缝检查通过。性能门槛再次通过：中画质曲面拖动事件到下一帧 P95 约 27.7 ms，帧间隔 P95 约 29.1 ms；首次模型加载约 3.7 秒，4K 导入约 3.6 秒，保存约 0.50 秒。投影覆盖层每个车身网格只创建一份，部件网格按需创建并复用；没有普通图案的视图跳过纹理采样，原厂底漆无普通图案时隐藏空覆盖层。

## 2026-11-08 镜头与 FOV 重构

`node --test tools/test/camera-navigation.test.cjs` 的 6 项数学测试通过：旋转和切换方向不改变镜头距离与 FOV，30 轮不同 FOV 往返没有累计缩放，平移符合屏幕像素比例，推进保持鼠标锚点，准确俯视与异常输入保持有限值，不同窗口比例与镜头能容纳整车八个边界顶点。

`node tools/camera-navigation-acceptance.cjs` 的 39 项真实 Electron 检查通过。通过车身的 `onBeforeRender` 读取实际投影，验证 15°、30°、50°、70°、90° 下主体投影范围保持一致，回到原 FOV 后恢复原距离；验证原配置器的侧栏偏移不再进入编辑画面。覆盖左键旋转、三种平移、滚轮锚点推进、Alt + 滚轮、双击聚焦、素材聚焦、Home 适配、Esc 手势回退、往返车辆配置恢复镜头，以及焦点在 3D 时的复制、撤销、重做、删除和取消选中。离屏输出验证当前镜头和自定义 FOV / 90° 俯视，且不改变交互相机。1920×1080、1366×768、900×650、720×520 CSS 视口检查并截图核对，短视口改用横向工具栏，点击按钮不再滚动整个 3D 容器。

本轮 30 次滚轮事件的同步处理 P95 为 17 ms，包含实际模型射线拾取；该数值不是输入到显示器的完整延迟。镜头没有新增常驻动画或轮询，重绘与状态上报按帧合并，聚焦的部件姿态矩阵每个网格只计算一次。记录和截图位于 `tools/acceptance/camera-navigation/`。

改动后的实际编辑回归 49 项、投影覆盖 21 项、Electron + Rust 全链路 17 项均通过。参考机器中画质性能门槛再次通过：曲面拖动事件到下一帧 P95 为 27.1 ms，帧间隔 P95 为 29.1 ms，曲面重算 P95 为 15.4 ms；首次模型加载 3.71 秒，4K 导入 3.57 秒，保存 0.51 秒。完整采样见 `tools/acceptance/performance/verification.json`。本次界面与桥接代码由 Rust 静态服务直接加载，运行文件清单包含新增相机模块，无需重编译后端或 Electron 宿主。
