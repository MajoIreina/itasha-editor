# NEXT 接口与车型适配

React 通过 [Tauri bridge](../next/src/bridge/desktop.ts) 读取 Rust 快照并提交命令；[main.rs](../next/src-tauri/src/main.rs) 负责命令注册，命令实现集中在 [commands](../next/src-tauri/src/commands)，权限以 [build.rs](../next/src-tauri/build.rs) 和 [capabilities/main.json](../next/src-tauri/capabilities/main.json) 为准。核心操作包括 read_view、execute、close_clean、choose_directory、import_image/asset_bytes，以及 viewport_* 原生视口命令。

Rust 使用工程 ID、session epoch 与修订防止过期操作；图像和几何通过受限资源句柄或二进制 IPC 传输。前端不传任意模型路径作为业务文件访问接口。

## 车型边界

- `next/catalog/vehicles.json` 提供车型与基础选配；目录来源是根 config/vehicles 的数据。
- 当前原生模型适配在 [adapters/su7.rs](../next/src-tauri/src/adapters/su7.rs)，仅接入 SU7 Max；其他车型的目录入口不代表模型已实现。
- 基础四轴为车漆、轮组、内饰、方向盘。黑化套装和碳纤维等独立轴按具体车型后续接入，不能宣称当前已完成。
- 通用渲染器保留在 renderer crate，车型差异进入适配层。不得把 SU7 网格、材质、尺寸、坐标和哈希直接复用于其他车型。
- 原始模型、解密原件、兼容修复与软件导出分别保存；资源处理优先使用本地小米适配技能。

## 工程兼容

NEXT 使用独立 app_data_dir 与 `studio.itasha.editor.next` 标识。旧 `.su7design` 迁移和施工导出尚未接入。

当前 NEXT 文档更换漆面版本时，适配器按 v21/v22/v23/v24 的旧源三角 ID 和源重心定位新片，保持世界位置、物理尺寸和图片方向。当前文档与撤销/重做历史全部迁移成功才一次提交；旧锚点落在被剔除的背面或缺少对应旧图时返回 `paint-migration-unavailable`，保持原工程不变。仓库保留 v21/v24；v22/v23 需另行恢复原映射才能迁移。此流程不等同于旧 `.su7design` 格式迁移。验证与限制见 [整车跨面复查](整车跨面复查-2026-11-17.md)。

`viewport_surface` 的二进制遮罩为 little-endian float64：每三角形 6 个值（归一化 x/y 三顶点），字节数为 `triangles * 6 * 8`；前端用 `Float64Array` 解码。归一化在提升到 f64 后计算，避免将有效微片再次压成线。此流仅服务 2D 遮罩，原映射和世界几何仍保留既有存储精度。
