# 接口与车型适配

## HTTP v1

`GET /__studio_health` 返回后端、应用版本与 `apiVersion: 1`。宿主使用随机令牌与同源 HttpOnly Cookie；业务 POST 需要 `X-Studio-Request: 1`。错误返回 HTTP 400 与 `{ "error": "可读错误" }`。

| POST /__api/ 操作 | 主要输入 | 输出 |
| --- | --- | --- |
| `projects` | 无 | `projects: [{name,file,modified}]` |
| `open` | `file` | `project` |
| `save` | `project` | `file,path` |
| `decode-image` | `name,data`（data URI/base64） | `name,data,note` |
| `import` | 本机绝对 `path` | 与解码相同 |
| `export` | `name,data,base64`，附加制作参数或 ZIP 内容 | 输出文件信息 |
| `performance` | 无 | 性能设置与实际生效状态 |
| `performance-update` | `multithreading,threads,gpuAcceleration` | 保存后的状态 |
| `vehicle-state` | 无 | `vehicles` |

前端只通过 `ItashaAPI.request` 调用。排队保存使用 `prepare` 立即捕获序列化快照，避免等待期间的后续编辑混入本次写入。完整可执行契约见 `api.rs`、`export.rs` 与 `tools/acceptance-rust.cjs`。

线程数为 1 至逻辑处理器数的整数，目前控制原生图片解码任务并发。GPU 设置在宿主启动前读取，改变后重启生效。单张图片上限 48 MB、6400 万像素；解码有时间与资源上限。

工程保持 `format: su7-livery`、`version: 1`。素材、车面、车辆配置与曲面 patches 保留；撤销历史与 GPU 资源不入工程。Rust 不重新解释曲面 UV。临时文件落盘后在同目录原子替换。

## 车型约定

`config/vehicles.json` 为 schemaVersion 1。每项指定 `id,label,goodsId,itemId,ssuId,manifest,extras,assetRoot,adapter,baselineVerified`。车型按需加载，首页不同时读入所有模型。

`vehicles/<id>/backend-adapter.json` 为 schemaVersion 1，包含车型自己的 `configuration`、`cartTemplate` 和按存档文件名索引的 `materialOverrides`。

原 manifest 保留 URL、方法、请求体、状态、响应头与文件名。`assets.mi` 直接按原字节重放。Service Worker 把离线请求交给 `/__archive`；业务响应与脚本兼容分别位于 replay、patches。

前端部件映射和后端配置适配是两项工作。逐车型检查配置、网格与漆面、拾取、编辑阶段、跨缝 UV、保存恢复、导出与离线完整性。完成后写入该车型 `acceptance.json`（`complete: true`）才开放入口；抓取资源或展示外观不等于完整可编辑。

Su7Ultra 不同机盖样式分别映射和验收。用户模型导入仍需同标准模型包的引擎依赖、材质、UV 和部件约定，当前没有通用模型导入器。

连续坐标解决可视贴合与跨部件连续，不等于双曲率钣金的无损平面展开。制作仍需实车分片、尺寸测量和施工补偿，输出不作为自动裁切刀模。
